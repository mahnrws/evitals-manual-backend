2. Overview | 
eVitals is a Remote Patient Monitoring (RPM) and Chronic Care Management (CCM) platform. It gives practices a single workspace to enroll patients, capture vitals from connected devices, run scheduled follow-ups, and produce billing-ready evidence of service time.
System roles
Super Admin — platform-wide operator; provisions practices, admins, and programs (this volume).
Admin — cross-practice operator for a customer organisation.
Practice Admin — manages a single practice, its clinicians and patients.
Provider — clinician who reviews vitals and signs off billing.
Practice Caregiver — practice-employed caregiver running follow-ups.
System Caregiver — eVitals-employed shared caregiver serving multiple practices.
Patient — end user of the mobile companion app.

2. Overview | 2.1. How to Read This Guide
This guide is written as a Hierarchical Task Analysis (HTA). Every product feature is decomposed as follows:
Level | Meaning | Document Element
Module | A top-level capability (e.g. Programs, Billing). | Heading 1  —  "7. Practice List"
Sub-module | A screen or workflow inside the module. | Heading 2  —  "7.1 Practice List Dashboard"
Task | A distinct goal a user pursues on that screen. | Heading 3  —  "7.1.3 Open a Practice Detail"
Steps | Ordered actions required to complete the task. | Numbered list under "Steps"
UI Reference | Every visible field / control on the screen. | Two-column table under "UI Reference"
Task meta-box
Each task begins with a colored meta-box carrying:
Goal — the outcome the actor is trying to achieve.
Actor — the role(s) permitted to perform the task.
Access Path — the exact click-through from the sidebar (e.g. Sidebar → Programs → + Add Program).
Preconditions — what must be true before starting.
Outcome — what changes when the task completes successfully.
